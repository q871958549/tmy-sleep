# 长期迭代与开发计划

这份计划跟着 1.2.0 的取舍往下排。应用仍然免费、开源、数据留在这台手机上。声音和晃动用来回答「这一夜发生了什么」，不用来标深睡、浅睡或 REM。

参考过的开源做法：

- [Snore Detector](https://github.com/elgrande73/FOSS-snore-detector-android-app)：频段能量、最短持续时间、事件里的峰值和时长、可选短 WAV、麦克风前台服务。
- [Plees Tracker](https://github.com/vmiklos/plees-tracker)：长期维护的入睡记录、可删除的单次、CSV。它睡觉时不录音，作息历史可以学，监测不要照搬。
- [SleepMonitor](https://github.com/singalongsong1787/SleepMonitor)：中文报告和鼾声片段的交互可以看。用翻身去标睡眠阶段，这一步不学。

## 已经落地

| 版本 | 内容 |
| --- | --- |
| 1.0.0 | 作息、本地提醒、打卡、7 天统计、GitHub Releases 更新 |
| 1.1.0 | 去掉黄色双下划线；浅色 / 深色 / 跟随系统；「立即入睡」和本机次数 |
| 1.2.0 | 入睡页默认约 20% 亮度、滑杆、点时间暂时调亮；每条有时长和相对满幅峰值；鼾声要连续约两秒并落在 100–1000 Hz；异动要十秒内三次晃动 |

1.2.0 仍然要开着记录页，锁屏就停。不保存录音。

## 原则

1. 先让人核对得了，再把判定做严，最后才考虑模型。
2. 峰值继续标明是相对满幅，在没有校准前不写成房间分贝。
3. 录音只留被判定的短片段，不留整晚原始文件，不上传。
4. 锁屏后续记用麦克风前台服务，通知保持安静。用户要能随时停。
5. 每一版都升版本名和 `+` 后面的构建号，打新的 `v*` 标签。不改已发布的标签。

## 1.3.0 短片段，用来核对误报

目标：醒后能听一两下，判断是自己、电视，还是风扇。

任务：

- 设置里增加「保存短片段」，默认关闭。打开后写明文件只在这台手机上。
- 判定为鼾声或梦话时，留下大约 5 秒。单条可以删除，也可以关掉之后清掉全部片段。
- 时间线上这一条可以播放。异动不录音。
- 片段总占用设上限，超过就丢掉最早的。

验收：

- 关闭时磁盘上不出现新的音频文件。
- 打开后，一条鼾声能在应用里播放，删掉后文件消失。
- 杀进程再打开，没删的片段还在。
- 网页版说明不能录音，不出现播放按钮。

先不做：整晚录音、上传、分享给别人。

## 1.4.0 锁屏之后继续记

目标：屏幕可以灭，记录还在。现在「必须亮着才能记」和去睡觉是矛盾的。

任务：

- Android 使用 `microphone` 类型的前台服务，通知栏一条安静的「正在记录」，点通知回到记录页，通知上可以结束。
- 服务被系统杀掉时，把已经记下的事件先落盘，下次打开说明这次中断在什么时间。
- 记录页仍可调亮度；屏幕关掉之后亮度滑杆没有意义，服务不依赖页面活着。
- 权限说明写清：要麦克风，要在后台继续。用户拒绝后台时，退回「开着页面才记录」。

验收：

- 开始记录后锁屏一分钟，解开仍能看到这一分钟里新出现的事件。
- 从通知结束记录，回到主页能看到时间线。
- 不声明 `USE_EXACT_ALARM`。前台服务不要把整晚音频留在通知里。

先不做：iOS 后台录音。iOS 工程先保持能编译，后台能力单独验证后再写进版本说明。

## 1.5.0 阈值自己调，记录能导出

目标：不同房间的底噪不一样，人要能把风扇从鼾声里挪出去。导出是为了自己留档，不是为了上传。

任务：

- 设置里给响度、最短持续秒数、晃动次数各一个有限度的调节，并有「恢复默认」。
- 调节只影响之后的新记录。
- 导出某一夜或全部事件为 CSV：开始、结束、种类、时长、相对峰值。短片段不进 CSV，导出说明里告诉人音频要在应用里另存。
- 历史列表可以删掉一整夜。保留最近记录的上限从现在的 30 次再看实际体积决定。

验收：

- 把响度门槛调高之后，原来会记上的轻声不再出现，调回默认后恢复。
- CSV 用表格打开，时间和种类跟应用里一致。
- 删掉一夜之后，主页和导出都不再出现它。

## 再往后

只在 1.3 的短片段积累出误报样子之后，才考虑在手机上跑一个小模型。模型必须能关掉，退回 1.2 的规则。没有片段对照时，不引入神经网络。

深睡、浅睡、REM、呼吸暂停诊断、手环、账号和云同步，继续留在外面。

## 每一版的开发顺序

1. 改 `pubspec.yaml` 的版本名，并把 `+` 后的构建号加一。
2. 先写失败的测试，再改记录规则或界面。
3. `flutter analyze` 和 `flutter test` 通过。
4. 网页上走一遍主页、记录页和设置；亮度滑杆和文案在网页上也能看见。真机夜录在发版说明里单独写有没有做。
5. 提交到功能分支，推送，更新拉取请求。
6. 测试通过后打新的 `v*` 标签。Actions 挂上 APK。已发布的标签不动。
